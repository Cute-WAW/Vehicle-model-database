# 阶段二：LightGBM 建模方案冻结说明

> 记录日期：2026-04-15
> 对应阶段：`LightGBM模型改造实施清单.md` 阶段 2「冻结 LightGBM 建模方案」

## 1. 目标

本阶段的目标不是开始实现 `LightGBM`，而是把首版方案中的关键决策一次冻结，确保进入阶段 3 和阶段 4 后，不再反复讨论以下问题：

- 预测目标到底是“价格”还是“残值率”
- 首版保留哪些旧逻辑
- 模型切换开关如何设计
- 新模型文件放在哪里、怎么命名
- 训练时采用什么数据口径与评估方式
- 什么样的预测应记为异常样本

## 2. 首版范围

首版 `LightGBM` 只替换“主残值模型”这一个环节，以下能力继续保留，不在本阶段替换范围内：

1. 相似车检索与 `confidence_dynamic` 微调
2. `C2B2C` 价格矩阵生成
3. `/predict` 现有请求与响应结构
4. 旧 `curve` 模型并存与回退能力

换句话说，首版改造不是重写整个价格预测系统，而是在现有链路中把“曲线残值模型”替换为“可切换的 LightGBM 残值模型”。

## 3. 目标变量与预测口径

### 3.1 目标变量

首版 `LightGBM` 的目标变量固定为：

- `残值率`

定义口径固定为：

```text
残值率 = 车况校正价 / 新车的价格
```

对应现有项目的训练口径，与当前 `curve` 模型保持一致。

### 3.2 预测口径

首版 `LightGBM` 统一采用以下预测口径：

1. 模型直接预测 `residual_rate`
2. 再根据 `new_price` 计算 `predicted_price`

换算公式固定为：

```text
predicted_price = residual_rate * new_price
```

### 3.3 输出约束

首版 `LightGBM` 输出残值率时，统一执行以下约束：

- 预测后的原始残值率必须裁剪到 `[0, 1]`
- 再用裁剪后的残值率换算价格

这样做的目的是与现有业务语义保持一致，避免出现负价格或高于新车价的异常结果。

## 5. 训练策略冻结

### 5.1 训练数据来源

首版 `LightGBM` 训练数据优先级固定为：

1. `output/merged_residual_value_data_with_dates.csv`
2. `output/merged_residual_value_data.csv`

说明：

- 优先使用带交易日期的数据，便于后续按时间切分验证集
- 如果日期版本数据不存在，再回退到不带日期的融合数据

### 5.2 数据清洗口径

首版数据清洗沿用当前 `curve` 体系的基本业务口径：

1. `新车的价格 > 0`
2. `使用年限` 必须可解析且在业务合理范围内
3. `行驶里程` 必须可解析
4. 目标值 `残值率` 按统一公式计算
5. 明显异常的残值率样本需要被过滤

这里的原则是“先与旧模型保持口径一致，再比较模型能力”，避免因为清洗规则漂移导致实验不具备可比性。

### 5.3 类别特征处理

首版 `LightGBM` 采用以下策略：

- 使用 `LightGBMRegressor`
- 类别字段使用 `LightGBM` 原生类别特征能力
- 首版不做 one-hot 编码

这样做的原因：

1. 与 `LightGBM` 的能力相匹配
2. 降低高基数字段的维度膨胀风险
3. 保持首版实现简单，减少与旧代码耦合

### 5.4 单调约束

首版固定保留以下业务约束：

- 对 `使用年限` 设置单调递减约束

说明：

- 该约束只对 `使用年限` 生效
- 其他特征首版不施加额外单调约束

### 5.5 训练/验证切分策略

验证集切分优先级固定为：

1. 如果训练数据包含交易日期，优先采用时间切分
2. 如果没有可用日期字段，再退化为固定随机种子的随机切分

冻结这个策略的原因是：

- 时间切分更接近真实上线场景
- 可以更真实反映模型对未来样本的泛化能力

### 5.6 评估指标

首版离线评估固定输出以下指标：

- `MAE`
- `MAPE`
- `R²`

同时需要与阶段一已记录的旧 `curve` 基线做同口径对比。

## 6. 异常预测样本定义

阶段 2 先冻结“定义与记录方式”，阶段 3 再实际产出样本与比例。

### 6.1 异常样本判定规则

以下任一情况成立，即判定为异常预测样本：

1. 原始预测值为 `NaN`
2. 原始预测值为 `Inf` 或 `-Inf`
3. 原始残值率 `< 0`
4. 原始残值率 `> 1`
5. 裁剪前后数值发生变化

### 6.2 异常比例定义

异常比例固定定义为：

```text
异常样本数 / 成功预测样本数
```

### 6.3 异常样本记录字段

阶段 3 实现时，异常样本明细至少输出以下字段：

- 样本行号或唯一标识
- `品牌车系`
- `使用年限`
- `新车的价格`
- `行驶里程`
- 原始预测残值率
- 裁剪后残值率
- 实际残值率
- 异常类型

## 7. 模型开关策略冻结

### 7.1 开关目标

模型开关的目标不是“上线即默认切主”，而是：

1. 支持 `curve` 与 `lightgbm` 并存
2. 支持在不改接口结构的前提下切换模型家族
3. 在 `lightgbm` 失败时保留回退到 `curve` 的能力

### 7.2 模型家族取值

统一模型家族取值固定为：

- `curve`
- `lightgbm`

### 7.3 默认值

首版默认模型家族固定为：

- `curve`

原因：

- 当前线上已稳定运行的是 `curve`
- `LightGBM` 在完成阶段 5 评估前不应直接成为默认主模型

### 7.4 回退策略

当模型家族选择为 `lightgbm` 时，首版统一采用以下策略：

1. 先尝试 `LightGBM` 品牌车系模型
2. 失败时再尝试 `LightGBM` 车型类别模型
3. 如果 `LightGBM` 都失败，并且允许回退，则回退到旧 `curve`

### 7.5 配置形式

首版建议新增独立配置文件：

- `config/model_strategy.yaml`

建议字段如下：

```yaml
default_model_family: curve
allow_curve_fallback: true
```

说明：

- 这是阶段 2 冻结的配置形式建议
- 阶段 3/4 再真正实现读取逻辑

## 8. 目录与命名规范冻结

### 8.1 目录规范

首版 `LightGBM` 训练产物统一放在：

- `output/lightgbm/brand_series_models`
- `output/lightgbm/car_types_models`
- `output/lightgbm/reports`

### 8.2 不新增分段目录

首版 `LightGBM` 不新增 `segmented_models` 目录。

原因：

1. `LightGBM` 首版已经引入多特征建模，不再沿用旧 `curve` 的车龄分段训练思路
2. 可以降低模型目录复杂度
3. 避免新旧两套“分段”概念混淆

### 8.3 文件命名规范

品牌车系模型命名：

```text
output/lightgbm/brand_series_models/<safe_filename(品牌车系)>.pkl
```

车型类别模型命名：

```text
output/lightgbm/car_types_models/<safe_filename(车辆类别)>.pkl
```

评估与报告产物命名：

- `output/lightgbm/reports/training_summary.csv`
- `output/lightgbm/reports/eval_summary.json`
- `output/lightgbm/reports/abnormal_predictions.csv`

- 首版保留旧模型并存
- 首版保留相似车修正与 `C2B2C`
- 首版开关策略采用 `curve` / `lightgbm`
