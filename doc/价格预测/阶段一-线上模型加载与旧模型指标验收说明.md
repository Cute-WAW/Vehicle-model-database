## 1. 验收结论

阶段一的两个验收点已具备可落地的文档答案。

### 1.1 当前线上到底加载哪类模型、从哪里加载

按当前仓库内的部署入口和启动配置，线上 `/predict` 走的是下面这条链路：

`src/web_predictor_debug_step5.py`
-> `src/residual_predictor_step5.py`
-> `src/price_predictor_step5.py`
-> `src/price_logic_step6.py`

其中实际加载的是 `curve` 体系模型，而不是 `LightGBM`：

1. 主模型类型：
   - 品牌车系曲线模型
   - 品牌车系分段曲线模型
   - 车型类别曲线模型（兜底）
2. 候选曲线函数：
   - `Exponential`
   - `Polynomial`
   - `Power`
3. 运行时加载顺序：
   - 先尝试 `output/segmented_models`
   - 再回退 `output/brand_series_models`
   - 再回退 `output/car_types_models`
4. 对外 `/predict` 返回结果并不只是曲线模型裸输出，还会继续叠加：
   - 相似车检索与 `confidence_dynamic` 微调
   - 启发式规则修正
   - `C2B2C` 价格矩阵生成

因此，当前线上主模型可以明确描述为：

> 当前线上加载的是 `curve` 残值模型体系，运行时优先使用品牌车系分段模型，其次全量品牌车系模型，最后回退车型类别模型；模型文件默认从 `output/segmented_models`、`output/brand_series_models`、`output/car_types_models` 读取。

## 2. 证据链

### 2.1 线上启动入口

当前 Web 服务启动入口是 `src/web_predictor_debug_step5.py`。

证据：

- `Dockerfile` 使用：
  - `python src/web_predictor_debug_step5.py --port 8087 --host 0.0.0.0`
- `docker-compose.prod.yml` 使用：
  - `python src/web_predictor_debug_step5.py --port 8087 --host 0.0.0.0`
- `docker-compose.aliyun.yml` 使用：
  - `python src/web_predictor_debug_step5.py --port 8087 --host 0.0.0.0`

这三处都没有传入任何模型目录覆盖参数。

### 2.2 预测器初始化方式

`src/web_predictor_debug_step5.py` 的启动阶段直接创建：

```python
predictor = ResidualPredictor(residual_data_csv=str(data_path))
```

这里显式只传了成交数据 CSV 路径，没有传 `brand_series_model_dir`、`car_types_model_dir`、`segmented_model_dir`，因此运行时会走代码默认模型目录。

### 2.3 默认模型目录

共享路径定义位于 `src/model_paths.py`，当前统一约定为：

- `output/brand_series_models`
- `output/car_types_models`
- `output/segmented_models`

`src/price_predictor_step5.py` 初始化时直接从该共享路径读取默认目录。

### 2.4 默认模型回退顺序

`src/price_predictor_step5.py` 的逻辑是：

1. 先按车龄段加载分段品牌车系模型
2. 分段模型不存在时，回退全量品牌车系模型
3. `src/residual_predictor_step5.py` 中如果品牌车系模型失败，再回退车型类别模型

这说明当前线上并不是“只加载一个目录里的单一模型”，而是“按优先级依次尝试三类 curve 模型”。

## 3. 旧模型指标是否已足够用于后续对照实验

答案是：可以。

当前 `doc/价格预测` 下已经具备两套旧模型基线，足够作为后续 `LightGBM` 对照口径：

### 3.1 模型层旧指标

来源：`doc/价格预测/阶段一-当前curve指标基线记录.md`

| 口径 | 覆盖率 | MAE(万元) | MAPE | R² |
|:---|---:|---:|---:|---:|
| 品牌车系曲线模型 | 100.0% | 0.92 | 27.11% | 0.8730 |
| 车型类别曲线模型 | 100.0% | 1.26 | 41.81% | 0.8312 |
| 混合策略 | 100.0% | - | 27.11% | 0.8730 |

这套指标适合回答：

- 新模型本身是否优于旧 `curve`
- 品牌车系主模型是否优于旧品牌车系曲线模型
- 车型类别兜底模型是否优于旧兜底模型

### 3.2 `/predict` 整体链路旧指标

来源：

- `doc/价格预测/阶段一-当前curve指标基线记录.md`
- `doc/价格预测/优信拍真实成交数据测评报告.md`

| 指标 | 数值 |
|:---|---:|
| 总样本数 | 799 |
| API 成功率 | 39.05% |
| C2B 命中率 | 28.21% |
| B2B 命中率 | 42.95% |
| MAE | 0.532 万元 |
| MAPE | 18.77% |
| 中位数 APE | 13.03% |
| R² | 0.9466 |

这套指标适合回答：

- 新模型接入 `/predict` 后整体效果是否提升
- 提升来自模型本身，还是来自 `new_price` 推断、相似车修正或价格矩阵策略
