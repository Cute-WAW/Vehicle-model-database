# 新增一批数据标准操作手册

> 记录日期：2026-04-21
> 适用范围：向当前项目中新增一批“车易拍格式”的二手车交易数据，并让系统在相似车检索、数据索引和模型训练中使用这些新数据

## 1. 目的

本文档用于说明，当你拿到一批新的二手车交易数据，且其格式与：

- [cheyipai_data_clean.csv](d:\BaiduNetdiskDownload\车型库映射\车型库映射\data\cheyipai_data_clean.csv)

一致时，应该如何完成以下工作：

1. 清洗不规范数据
2. 进行车型库匹配
3. 提取结构化残值数据
4. 合并到当前线上使用的数据集
5. 如有需要，重训 `curve` / `lightgbm` 模型
6. 最后同步到服务器

## 2. 输入数据格式要求

新增数据应尽量整理为与以下文件一致的列结构：

- [cheyipai_data_clean.csv](d:\BaiduNetdiskDownload\车型库映射\车型库映射\data\cheyipai_data_clean.csv)

当前样例列名为：

1. `品牌`
2. `车型`
3. `上牌时间`
4. `行驶里程`
5. `颜色`
6. `城市`
7. `车况`
8. `是否营运`
9. `成交价格`
10. `成交时间`

建议字段语义如下：

- `品牌`：如 `大众`
- `车型`：如 `2024款 朗逸 300TSI DSG星空领先版`
- `上牌时间`：如 `2024年10月1日`
- `行驶里程`：建议为数值，单位“万公里”
- `颜色`：如 `白色`
- `城市`：如 `平顶山`
- `车况`：如 `80B`
- `是否营运`：如 `非营运`
- `成交价格`：建议为数值，单位“万元”
- `成交时间`：如 `11月28日`

## 3. 清洗要求

原始新增数据中常见的不规范情况包括：

1. 重复行
2. `成交价格` 缺失、为 `-`、为空字符串、带单位文本
3. `行驶里程` 缺失、为 `-`、为空字符串、带单位文本
4. `城市`、`颜色`、`是否营运` 字段缺失
5. `车型` 或 `上牌时间` 缺失
6. `车况` 缺失

### 3.1 现有参考清洗脚本

项目里已有两份参考脚本：

- [cheyipai_data_clean.py](d:\BaiduNetdiskDownload\车型库映射\车型库映射\tests\cheyipai_data_clean.py)
- [clean_cheyipai_more.py](d:\BaiduNetdiskDownload\车型库映射\车型库映射\tests\clean_cheyipai_more.py)

它们体现了当前项目默认接受的清洗原则：

1. 删除重复行
2. 去掉 `成交价格` 中的 `万` 等单位
3. 只保留能提取出数值的 `成交价格`
4. 删除 `车况` 缺失的记录
5. 用前值填充 `城市`、`颜色`
6. `是否营运` 缺失时默认填 `非营运`
7. `成交时间` 缺失时用固定默认值兜底
8. 删除 `车型`、`上牌时间` 缺失的记录

### 3.2 推荐清洗口径

处理新增数据时，建议至少执行以下清洗：

1. 删除完全重复记录
2. 删除 `成交价格` 缺失记录
3. 将 `成交价格` 转换为纯数值（单位：万元）
4. 删除 `行驶里程` 缺失记录
5. 将 `行驶里程` 转换为纯数值（单位：万公里）
6. 删除 `车况` 缺失记录
7. 删除 `车型` 缺失记录
8. 删除 `上牌时间` 缺失记录
9. `城市` 缺失时可用前值补齐
10. `颜色` 缺失时可用前值补齐
11. `是否营运` 缺失时默认填 `非营运`

## 4. 标准操作流程

## 4.1 第一步：准备并清洗原始数据

将新增数据整理成与 [cheyipai_data_clean.csv](d:\BaiduNetdiskDownload\车型库映射\车型库映射\data\cheyipai_data_clean.csv) 相同的列结构后，保存到一个新文件，例如：

```text
data/cheyipai_data_increment_20260421.csv
```

先按参考脚本的规则完成清洗，再生成清洗后的标准文件，例如：

```text
data/cheyipai_data_increment_20260421_clean.csv
```

> 建议：
> 不要直接覆盖原始文件，保留一份原始数据备份，清洗后另存新文件。

## 4.2 第二步：执行车型库匹配

使用当前批量匹配脚本：

- [batch_match_step1.py](d:\BaiduNetdiskDownload\车型库映射\车型库映射\src\batch_match_step1.py)

执行命令：

```powershell
..\venv\Scripts\python.exe src\batch_match_step1.py --input data\cheyipai_data_increment_20260421_clean.csv --output output\cheyipai_match_result_increment_20260421.txt
```

说明：

- `--input` 指向你清洗后的新增数据
- `--output` 单独命名，避免覆盖历史匹配结果

匹配完成后，会生成类似以下格式的文本结果：

- `【输入】...`
- `【匹配】...`
- `【得分】...`

## 4.3 第三步：从匹配结果提取结构化残值数据

当前提取脚本：

- [extract_residual_data_step2.py](d:\BaiduNetdiskDownload\车型库映射\车型库映射\src\extract_residual_data_step2.py)

这个脚本默认读取：

- `output/youliang_match_result.txt`
- `output/youxinpai_match_result.txt`
- `output/cheyipai_match_result.txt`
- `output/batch_match_result.txt`

如果你新增的是一份单独命名的匹配结果文件，例如：

- `output/cheyipai_match_result_increment_20260421.txt`

那么有两种做法：

### 做法 A：临时替换标准文件名后执行

将新增匹配结果复制或重命名为：

```text
output/cheyipai_match_result.txt
```

然后执行：

```powershell
..\venv\Scripts\python.exe src\extract_residual_data_step2.py
```

### 做法 B：先手工并入已有标准匹配结果，再执行

将新匹配结果内容并入现有：

```text
output/cheyipai_match_result.txt
```

再执行：

```powershell
..\venv\Scripts\python.exe src\extract_residual_data_step2.py
```

执行后会更新或生成：

- [residual_value_data.csv](d:\BaiduNetdiskDownload\车型库映射\车型库映射\output\residual_value_data.csv)

## 4.4 第四步：合并到当前主数据集

当前线上主链路优先使用：

- [merged_residual_value_data_with_dates.csv](d:\BaiduNetdiskDownload\车型库映射\车型库映射\output\merged_residual_value_data_with_dates.csv)

因此，新增数据如果要被线上检索、新车价推断和默认索引使用，最终必须进入这份文件。

当前已有相关脚本：

- [merge_data_step6.py](d:\BaiduNetdiskDownload\车型库映射\车型库映射\src\merge_data_step6.py)
- [merge_new_data_step6.py](d:\BaiduNetdiskDownload\车型库映射\车型库映射\src\merge_new_data_step6.py)

推荐做法：

1. 先将新增数据提取结果合并到：
   - `output/merged_residual_value_data.csv`
2. 如新增数据带有可解析的交易时间，再进一步合并到：
   - `output/merged_residual_value_data_with_dates.csv`

> 注意：
> 当前项目的线上 `ResidualPredictor` 和微信端后端，都会优先读取 `merged_residual_value_data_with_dates.csv`。

## 4.5 第五步：删除索引缓存并重启服务

新增数据进入主数据集后，需要删除旧索引缓存：

```powershell
Remove-Item index\residual_data_index.pkl -Force
```

这样服务在下次启动时会基于新的数据文件重新构建索引。

如果你本地在运行 Web 服务或 Docker 服务，需要重启一次。

## 5. 如果要让新数据参与模型训练

如果你的目标不仅是“让相似车检索使用新数据”，而且还要“让 `curve` / `lightgbm` 学到这批新样本”，则在第 4 步之后，还要继续执行重训。

### 5.1 重训 curve 模型

品牌车系模型：

```powershell
..\venv\Scripts\python.exe src\build_brand_series_models_step4.py
```

车型类别模型：

```powershell
..\venv\Scripts\python.exe src\build_car_types_models_step4.py
```

分段模型：

```powershell
..\venv\Scripts\python.exe src\build_segmented_models_step4.py
```

### 5.2 重训 LightGBM 模型

```powershell
..\venv\Scripts\python.exe src\build_lightgbm_models.py --group-by both
```

## 6. 重训后建议执行的验证

### 6.1 对比评估

```powershell
..\venv\Scripts\python.exe experiment\compare_curve_vs_lightgbm.py --sample-size 300
```

### 6.2 细粒度质量验证

```powershell
..\venv\Scripts\python.exe experiment\quality_validation_lightgbm.py --sample-size 300
```

### 6.3 测试

```powershell
..\venv\Scripts\python.exe -m pytest tests\test_batch_modeling.py tests\test_lightgbm_model.py tests\test_dual_model_predictor.py tests\test_serialization.py -v
```

## 7. 最后一步：同步到远端服务器

如果本地验证无误，并且你希望把新数据、模型和配置同步到腾讯云与阿里云，执行：

```powershell
..\venv\Scripts\python.exe scripts\update_all_servers.py
```

## 8. 最小必需步骤总结

如果你只是想“让新增数据尽快在线上检索和推断中生效”，最少执行：

1. 清洗新增数据
2. 跑 [batch_match_step1.py](d:\BaiduNetdiskDownload\车型库映射\车型库映射\src\batch_match_step1.py)
3. 跑 [extract_residual_data_step2.py](d:\BaiduNetdiskDownload\车型库映射\车型库映射\src\extract_residual_data_step2.py)
4. 合并到 `merged_residual_value_data_with_dates.csv`
5. 删除 `index/residual_data_index.pkl`
6. 重启服务

如果你还想“让模型也学习到这批数据”，则再额外执行：

7. 重训 `curve`
8. 重训 `lightgbm`
9. 跑评估与测试
10. 同步服务器

## 9. 推荐命名规范

为了后续排查方便，建议新增批次使用日期命名，例如：

- 原始文件：`data/cheyipai_data_increment_20260421.csv`
- 清洗后文件：`data/cheyipai_data_increment_20260421_clean.csv`
- 匹配结果：`output/cheyipai_match_result_increment_20260421.txt`

这样可以清晰追踪每一批新增数据的处理过程。
